# MelliAtlas Specification Index

**Status: architecture bootstrap only.** No normative active sub-specification, implementation plan, feature cross-reference, or developer-controlled checkpoint exists yet.

When the developer selects a workstream:

1. Write a focused normative sub-spec with observable requirements, scope, security, failures, boundaries, and acceptance tests.
2. Supply a **separate, linked implementation plan** for that sub-spec, with verified/proposed paths and executable verification guidance.
3. Mark both documents draft until explicitly accepted; do not advance workflow state on the basis of generated files, successful tests, or a patch archive.
4. Archive accepted sub-specs together with their plans; keep this index and owner documentation synchronized.

`active/` and `archive/` are empty by design. Requirements and implementation are not implied by the directory names.
